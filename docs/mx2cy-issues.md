# modelx-cython / exporter issues found while building BondPortfolio

These are inputs to plan Phase 5, which improves modelx-cython. Each entry gives the workaround the model used before Phase 5. The status of each issue after Phase 5, and two issues found during it, are in [Status after Phase 5](#status-after-phase-5) below.

| # | Issue | Where | Model workaround today |
|---|---|---|---|
| 1 | Uncached Cells are never traced, so they compile untyped: `object` arguments and return, with the body run on Python objects. | `tracer.py` `MxCodeFilter` (~589-603) admits `_f_*` only | None. The canonical Lib/Dates helpers are uncached, so hot callers pay Python-call costs. |
| 2 | No way to set Cython compiler directives such as `infer_types`. Integer loop variables and locals used in arithmetic stay Python objects. | `cli.py` setup.py generation (~552-601) | None. |
| 3 | `math.exp`/`log`/`pow` through a module reference stay Python calls. | (no lowering) | None. Wrapped in `float(...)` so locals stay C doubles. |
| 4 | Exported and compiled Spaces are self-cyclic (`_space`, `_mx_roots`), so `del Space[key]` frees nothing until a full GC. | `modelx/export/exporter.py` (~545, 657-665, 731-734); `_mx_sys.pxd` | The driver calls `gc.collect()` after `del`. |
| 5 | A Cells returning a NON-numeric numpy array (e.g. a `<U10` str array) is typed with its element type (`str`) instead of `object`. Calling it in the compiled model raises `TypeError: Expected str, got numpy.ndarray`. | `builder.py` `get_rettype_expr`: the non-real array case falls through to `return typ` | `Legs.iso_column` returns a list. |
| 6 | A Python name that is a Cython keyword (e.g. a parameter named `include`) produces an invalid `.pxd` ("Expected ')', found 'include'"). | transformer / pxd emission | Model lint forbids Cython keywords. mx2cy could reject them with a clear message, or rename them. |
| 7 | `{float, numpy.float64}` argument mixes are typed `object`, silently: only Integral mixes are logged. | `tracer.py` `_init_arg_types` (~191-212) | Model rule: wrap float reads and float arguments in `float(...)`. |
| 8 | `TransSpec.param_type` exists in the spec but is never consumed, so argument types cannot be overridden. | `config.py` | None. |
| 9 | MSVC warns C4048 ("different array subscripts: `int (*)[2]` and `int [12000][3]`", likewise for `double`) in the `__pyx_unpickle__c_Valuation__set_state` function Cython generates for auto-pickling. One stack temporary of the widest `[MAX_BONDS][k]` shape is reused for every `[MAX_BONDS][k']` cache array, here the `[12000][2]` arrays of `Valuation.solve(b, kind)`. It is harmless: each row is converted at the narrower stride and `memcpy`'d with the narrower size, and only unpickling runs it. | Cython auto-pickling of the generated cdef classes; mx2cy could emit `@cython.auto_pickle(False)` | None needed. The warning appears from Phase 4 on. |

## Status after Phase 5

The fixes are on the modelx-cython branch `bondportfolio/mx2cy-improvements` (from `main` 0f3e564, not yet merged or released). A review of the branch found that typing uncached Cells could break models that compile on `main`, and a few smaller problems; the fixes are folded into the rows below. They do not change the BondPortfolio translation: the generated `.pxd` and `.py` files are identical before and after them. Build BondPortfolio with it by setting `MODELX_CYTHON_SRC` to a checkout of that branch before running `tools/build_cy.py`. The measurements are in docs/performance.md, "Phase 5".

| # | Status | BondPortfolio now |
|---|---|---|
| 1 | **Fixed on the branch.** The tracer records the public methods of uncached Cells, which compile as typed `cpdef` functions without a cache. After review, typing them no longer breaks models that compiled before: a parameter whose default is not a literal of its traced type (`y=None` for a float, `k=0.5` for an int), or that the formula binds to a value not provably of that type (`rate = rate / 100`, `t = max(t, 0.5)`, `t /= 2`), is typed `object` and logged; for a cached Cells only in its `_f_` formula, so its cache keeps the C array. And a real array returned by an uncached Cells that no formula uses is returned as the array, not a memoryview. | 52 of the 60 uncached Cells come out with C types (or `str`). The other 8 are listed, with the reason, in `tools/build_cy.py` `UNCACHED_OBJECT_CELLS`: `Data.read_table` (a DataFrame); `Lib.long_date` and `Dates.daycounter_name` (`str`, error messages only); and five Lib helpers the model never calls (`cxx_lround`, `cxx_idiv`, `cxx_irem`, `implied_rate_dates`, `equivalent_rate_dates`). `tools/cy/sample.py` calls the two helpers that hot Cells reach only on rare branches (`is_odd_integer` through `cxx_pow`'s overflow and domain branches, and `close_enough`). The pxd audit now covers uncached Cells too, so a build with `main` fails it (52 uncached Cells typed `object`). This is the largest gain of Phase 5: valuation takes 27% less time at level 1 and 44% less at level 2 (10,000 bonds). |
| 2 | **Fixed on the branch:** spec key `compiler_directives`. | `tools/build_cy.py --directive infer_types=True` (or `BONDPORTFOLIO_CY_DIRECTIVES`); off by default. With `infer_types=True` the build passes `pytest -m compiled` and the benchmark's byte-identity check. It types 69 more locals as `long long`, 10 more as `Py_ssize_t`, and 4 as the 32-bit C `long` that the modelx-cython docs warn about. Those 4 are counters bounded far below 2^31: `Valuation.n_expired` / `n_tradable` (`count`), `Valuation.sign_ok` (`signChanges`) and `Bond.schedule` (`periods`). Gain: 0 to 7% alone, 2 to 11% on top of `use_libm`. Re-check the new `long` locals whenever the model changes. After review, the branch rejects the directive values that would silently change results: `cpow=True`, `language_level=2`, `annotation_typing=False` and `legacy_implicit_noexcept=True`. |
| 3 | **Partly fixed on the branch:** spec key `use_libm` (opt-in). After review, a `**` on a rewritten call is rewritten too (`max(math.exp(x) ** 0.5, 1.0)` failed to compile with "complex types are unordered"), and so is a call on a rewritten `**` (`math.exp(x ** 2.0)`). | `tools/build_cy.py --use-libm` (or `BONDPORTFOLIO_CY_LIBM=1`); off by default. Three sites are rewritten to C calls: `math.exp(x)` in `Lib.cxx_exp`, `math.pow(x, y)` in `Lib.cxx_pow`, and `math.log(compound)` in `Lib.implied_rate`. The build passes `pytest -m compiled` and the byte-identity check. Gain: 12 to 14% at level 1 and 20% at level 2. The two hot ZeroCurve sites, `math.exp(-r * tt)` in `Valuation.discount_core` and `Valuation.zs_discount_kd`, stay Python calls; see #10. |
| 4 | **Open.** This is in the exporter, out of scope for this branch. | The driver still calls `gc.collect()` after each `del`. |
| 5 | **Fixed on the branch.** A non-real or 0-d array return is typed `object`. | `Legs.iso_column` still returns a list; no model change was needed. |
| 6 | **Fixed on the branch.** mx2cy rejects Cython keywords, C macros and C type words with a `ReservedNameError` that lists each name, before the sample run (C type words, which depend on the types, after it). After review, the macro list also covers MSVC's `math.h` (`DOMAIN`, `OVERFLOW`, ...), the POSIX error numbers, and macros of `pyconfig.h`, `structmember.h` and `object.h`; it is still not exhaustive, and a macro it misses still fails at C compile time. An error found after the sample run (a C type word, an invalid `return_type` or `param_type`) now leaves the previous output in place: the output is rotated to `_BAK1` and the model copied only after every check. | The model lint `test_no_cython_reserved_names` stays. It is stricter (it also checks locals and the C type words) and fails before any build. |
| 7 | **Fixed on the branch.** A `{float, numpy.float64}` mix is typed `double`; after review, only `float` and its subclasses widen so, and a mix with `numpy.float32`, `numpy.longdouble` or `Fraction` stays `object`. Every argument that falls back to `object` is logged at `INFO`. | The BondPortfolio build logs no such fallback. The `float(...)` rule stays: an `{int, float}` mix is still `object`, and the wraps are what keep locals C doubles. |
| 8 | **Fixed on the branch:** `param_type` overrides parameter types. | Not used: every parameter is typed from the trace. |
| 9 | **Open.** | The two C4048 warnings appear in every build: the default one and those with `infer_types`, with `use_libm`, and with both. |
| 10 | **New, open.** `use_libm` (and the `**` rewrite) rewrite a call only when its arguments are *provably* C numbers. The classifier treats every local variable as unknown, even one that Cython types as a C double. Where: `modelx_cython/powers.py` (the operand classifier; logged as "math call left as exported ... not all provably C numbers"). | `math.exp(-r * tt)` in `Valuation.discount_core` (the ZeroCurve discount) and `Valuation.zs_discount_kd` (the spreaded discount) stay Python calls, with `r` and `tt` locals. Two possible fixes in mx2cy: treat a local as floating when every assignment to it in the formula is provably floating, or treat a call of the builtin `float(...)` as floating. The second would need `math.exp(float(-r * tt))` in the model. |
| 11 | **Fixed on the branch (cosmetic).** The `INFO` messages of the `**` and `math` rewrites, and those of the usage analysis and the spec checks, named an uncached Cells by a `_f_<name>` method that does not exist, e.g. `..._c_Valuation._f_zs_discount_kd` for the method `zs_discount_kd`. They now name the method that holds the formula (`CombinedCellsInfo.formula_fqname`). | None needed. |
